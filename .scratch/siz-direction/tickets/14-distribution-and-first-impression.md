# 14 — Why would a passer-by try siz?

Labels: `wayfinder:grilling`
Status: open
Claimed by: —
Blocked by: 13

## Question

Siz has 0 stars and ~200 downloads a month after two months, with **no distribution attempt made at all** — no demo, no badges, no docs site, no announcement anywhere. That is not evidence the tool is unwanted; it is the absence of evidence either way. This ticket decides how to get some.

- What does someone see in the first ten seconds — and what should they? A terminal recording of the audit failing on a real repo says more than any paragraph.
- Does the README open with the problem or the feature list? (It currently opens with a checklist of 40+ entries, which reads as a changelog.)
- Badges, a docs site, or neither? A docs site for a single-binary CLI may be overhead that never pays back.
- Where would the announcement go, and what is the artifact that gets announced — a release, a blog post, a workflow snippet people copy?
- Is there a smaller move first: does siz's own repository dogfood its own audit in CI, visibly?
- What is the honest success signal at, say, three months — stars, downloads, one external issue from a real user? Pick one, so the next decision has evidence.

## Why it is on the route rather than deferred

The map's premise is that positioning, not visibility, is the problem — but that premise is untested precisely *because* visibility was never tried. Deciding the distribution move is what makes the next round of this discussion evidence-based instead of speculative.

## What would resolve this

An agreed first-impression plan: the demo artifact, the README opening, the badge/docs-site call, the announcement channel and artifact, whether siz dogfoods its own audit, and one chosen success signal with a date. Concrete enough that the final spec can carry it as work items.
